掃描模式
完整模式會送出進階探測請求： 成對的唯讀 SQL 條件、路徑遍歷字串，以及唯一的 SSRF callback URL。檢查仍為非破壞性，但只應對已取得書面授權的目標使用。

登入後掃描 選填

先完成登入，再讓掃描器帶著 session 探索需要登入的頁面。

表單登入會自動讀取登入頁的 CSRF token，並在成功後把 Cookie 帶入掃描。 若網站使用 JavaScript 登入、SSO、MFA 或 localStorage token，請改用下方的瀏覽器狀態檔。
先用 vulnscan login --url ... 開啟瀏覽器完成 SSO／MFA／JavaScript 登入， 再把產生的 storage state JSON 上傳。掃描器會擷取符合 scope 的 Cookie； 若有 localStorage token，可選擇映射到自訂 Header。
按下方按鈕會在這台電腦開啟 Chromium；請完成 SSO／MFA／JavaScript 登入， 回到此頁按「我已完成登入」。需要先安裝 pip install -e ".[browser]" 與 playwright install chromium。
憑證不會保存：密碼、Cookie、Header 值與 storage state 只存在本次掃描的記憶體中， 不寫入 SQLite、報告或 scope 快照；表單驗證失敗後需重新輸入。

BOLA／BFLA 雙帳號唯讀檢查 選填

使用主要帳號與第二帳號讀取物件或管理 GET URL；只做 GET，不枚舉、不保存回應內容。

API 掃描（OpenAPI 匯入）

上傳 OpenAPI 3 或 Swagger 2 JSON/YAML，或提供規格 URL；掃描器會匯入 GET／POST 端點。

內建上限：一次最多 50 個目標、250 個展開後的起始 URL；主動檢查另有測試預算，避免造成負擔。
